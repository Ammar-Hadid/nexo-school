# Model selection for task creation and review — D13

22 October 2026. **Research completed; model selection and benchmark execution proposed.** The user requested a cross-provider investigation, including different generators for different task types, after questioning the original Anthropic choice. This revisits ADR-007's initial provider preference; it does not approve a replacement, live spending, educational content or automatic publication.

## Recommendation

Keep arithmetic generation and answer checking deterministic. For semantic generation, compare economical models on constrained language/spelling tasks and stronger models on passage/question bundles. Select the reviewer separately, based first on missed serious defects and then false alarms, unresolved cases, human review time and cost. There is no measured Dutch educational winner yet.

My proposed first D13 field is **eight models across four providers**: GPT-6 Luna, Claude Haiku 5.5, Mistral Small 4, Gemini 3.8 Flash, GPT-6.1 Sol, Claude Sonnet 5.5, Claude Opus 5.5 and Gemini 4 Argon. This is a manageable comparison of economical, middle and stronger tiers, rather than eight guesses at the same job. It deliberately tests the Anthropic assumption against other providers. These are candidate-selection judgments, not quality rankings.

Premium GPT-6 Astra and Claude Fable 5.1 are optional reference candidates on a shared difficult subset if the core group leaves important failures unresolved. A more expensive model is not reference truth. Qwen3.8 Flash is the first additional low-cost challenger if we widen the field; DeepSeek V4.1 Flash is another credible alternative.

My strongest initial quality/value hypotheses for longer writing are **Sonnet 5.5 and GPT-6.1 Sol**; Argon and Opus test whether more reasoning/expense produces fewer corrections. My economical hypotheses for short items are **Haiku 5.5 and GPT-6 Luna**, with **Mistral Small 4** a deliberately competitive alternative. None is an endorsement before measurement. I would not assume the cheapest writer is a sufficiently careful reviewer.

Deterministic structure does not certify AI-authored word-problem text. Nor does choosing a strong model approve curriculum mapping, learner ability judgments or personalized explanations. Those remain governed by their existing task contracts.

Do not promise an entire benchmark fits €10 until its exact manifests, maxima, remaining shared allowance and receipts are known.

## Proposed experiment, in order

1. **Freeze human references first.** Adjudicate the existing 12 development fixtures, then build a proposed 40-item screening set and a separate 40-item holdout. Forty is a practical screening size, not a validated sample-size threshold. Balance clean/defective cases and cover arithmetic/word problems, Taal, Spelling and reading, with several independent families/passages. Predefine serious wrong keys, multiple valid answers, missing passage evidence, units, objective mismatch, feedback leakage, malformed content and valid-but-unusual Dutch answers. Include content trying to instruct the reviewer to ignore its rubric. Preserve adjudicator decisions, hashes and disagreement resolution.
2. **Confirm adapters and budget on synthetic material.** After separate live-run authorization, use a small smoke subset to verify schemas, model identity, token accounting, truncation/refusal handling and cost reservation. This is an integration check, not a quality result. Freeze model/version, endpoint/region, prompt, schema, reasoning settings and token limits. Disable web/search/tools so each model receives the same evidence. Equal reasoning-setting names across vendors do not imply equal compute; record actual billable usage.
3. **Screen eight reviewers.** Use the same 40 candidates for each, with the existing separate concealed-key solve and full-content semantic requests. Both must conceal human labels. Keep responses independent. Continue reporting unresolved cases rather than turning abstention into a pass. Include every charged/retried/uncertain attempt. Repeat a predeclared subset to expose variability; repetition is not additional independent educational evidence.
4. **Measure creation separately.** Proposed initial set: eight short-item briefs, eight word-problem briefs and eight passage/bundle briefs, using the per-type comparisons above. Generate against the same explicit objectives, level/length constraints and allowed facts. Blind human reviewers to model identity and randomize display order. Record first-pass acceptance, critical defects, correction minutes, diversity, key/evidence validity and cost per usable accepted item. These generation samples must not replace the fixed adjudicated reviewer set or contaminate its holdout. This is a proposed companion experiment, not already implemented D13 generation support.
5. **Validate survivors.** Select the two or three most useful reviewer candidates on screening data, freeze any development changes, then run the unused holdout once. Split by family/passage, not trivial number substitutions. Report raw numerators/denominators per defect and content type. A small set with zero observed misses is not proof of a low real-world failure rate. Expand evidence before any safety claim or automatic-publication proposal.
6. **Choose routes, not one global winner.** Select the cheapest creator meeting each task's reviewed quality bar and a separately measured reviewer. Test cross-provider creator/reviewer pairings for actual residual errors. Provider diversity may reduce shared errors, but does not prove independence. Escalate uncertainty/disagreement to the human; no model's confidence or majority vote authorizes semantic publication.

LLM judges can exhibit position, verbosity and self-preference biases; this is why generation and review must have independent human references and blinded assessment. See the primary [MT-Bench judge study](https://arxiv.org/abs/2306.05685). We must measure whether reviewing saves Ammar time within the 15–30-minute weekly target, not merely count flags.

## Implementation and operating implications

OpenAI, Anthropic and Google document structured-output facilities: [OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs), [Anthropic](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [Google](https://ai.google.dev/gemini-api/docs/structured-output). Exact supported schema subsets and refusal/truncation behavior need adapter tests. Schema-valid JSON is not a factual or educational guarantee; preserve D13's application validation and exact-content binding.

The inspected runtime still uses `fake-v1`, fictional reservations, an 8,000-character request limit, a five-second timeout and bounded retries. The provider interface and database guard are fake-only. A real benchmark therefore requires a deliberate bounded adapter/policy migration, not just an API key or a different model string. Long reading bundles may need a reviewed request-size change; real reasoning may need different deadlines/leases. Preserve D12's atomic shared cap, idempotency, uncertain-cost handling and all-attempt accounting. Do not build a routing platform or adopt a new service merely to conduct this comparison.

Before a live run, verify exact provider/account access, model version, region, data use/retention, applicable terms, billable reasoning/output maxima and conservative euro conversion/tax treatment. Google's standard paid and free/contributor data-use terms differ on its pricing page; a free quota is not interchangeable with paid processing. This survey is not a full contractual/privacy review. Benchmark inputs remain synthetic; child data is unnecessary.

# Button redesign research

17 October 2026. Scope: revise the existing shared Button review after the user rejected its shape, padding and secondary hover/pressed treatment. This is desk research and a design recommendation, not user approval or usability-test evidence. This research used the then-approved Plum & Cornflower palette and Outfit typography. A subsequent user-requested lighter-purple trial is tracked in [the current color guide](color-palette.md); recommendations below retain their original research context.

## Diagnosis of revision 1

The current CSS darkens every background toward the same ink foreground using 12% on hover and 22% when pressed. For the secondary button, calculated ink-on-cornflower contrast falls from **6.95:1** to **5.73:1** and **4.83:1** respectively. These values use the WCAG relative-luminance formula with the CSS sRGB mixing proportions; they are calculations from source colors, not browser screenshot sampling. They meet the normal-text AA floor but reduce readability and leave little margin in the pressed state. The user's rejection is valid regardless of that minimum threshold.

The 12px corner radius, 48px default height and shared background-darkening rule are implemented proposals, not approved design decisions. Passing accessibility checks did not establish visual suitability.

## Recommended direction for the next review

- Use a restrained rounded rectangle: start with a **6px radius**, a roomier **52px default height**, and approximately **28px horizontal padding**. Preserve a compact 44px option and a larger touch-friendly option. These dimensions are a project-specific visual hypothesis responding to the user's feedback, not a finding that research proves one ideal radius.
- Keep plum as the strongest primary action. Use per-variant state tokens rather than one universal darkening formula.
- Keep ink labels on secondary cornflower surfaces. Prefer lighter blue tints or a clearer contrasting border for feedback, so hover and pressed states retain comfortable text contrast. A white surface with a plum outline remains the quieter alternative.
- Keep active feedback restrained and local; preserve a visible keyboard-focus outline with space around the button. Avoid adding ornamental gradients, exaggerated shadows or bouncy movement to the calm guardian workspace.
- Review the buttons in a realistic guardian action group as well as the complete state sheet. Check default, hover, pressed, focus, loading, disabled, selection and icon-only treatments at desktop and phone widths.

Implementation may tune these proposed values after visual inspection. Record final dimensions and measurements in the component review evidence, and keep the component unapproved until the user reviews the revision.

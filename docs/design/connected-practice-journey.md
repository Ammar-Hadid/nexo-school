## Review

Open [Practice → Connected journey → Review Page](http://127.0.0.1:6006/?path=/story/practice-connected-journey--review-page), or [the standalone journey](http://127.0.0.1:6006/iframe.html?id=practice-connected-journey--review-page&viewMode=story). The existing `components-practice-tasks--tasks-page` entry also mounts the connected preview, starting at the overview. Other task-status stories remain explicitly synthetic status/callback specimens; their historical status arguments do not seed real attempt history.

Choose **Bekijk taken**, start any task, answer, and use **Mijn taken** to leave and resume. **Ga verder** restores the current question, draft/choice, validation error or locked feedback. Complete original questions and any deferred retries to reach the existing result screen. **Terug naar mijn taken** updates that task to **Klaar!**; **Bekijk resultaat** reopens its unchanged result. Returning to **Mijn blokken** preserves all tasks and reflects factual completed-task counts.

The fixture is one available block with six tasks: two independently owned Rekenen tasks and one each for Taal, Spelling, Redactiesommen and Begrijpend Lezen. This is a demonstration assignment, not a new daily subject requirement. Both Rekenen tasks deliberately reuse the approved synthetic specimen to demonstrate isolation; this is not fresh-content selection or a repeat-assignment policy. Reading uses its complete six-paragraph passage and associated ten questions. The count comes from the bundle; ten is not a reading-session rule. The earlier overview's six-question reading example remains historical snapshot data, not the connected bundle.

Every connected page explains that progress is temporary and that refreshing or closing clears answers. Leaving this mounted Storybook story also discards state. No local/session storage, cookies, URL-serialized answers, backend writes or cross-tab synchronization are used. Navigation controls stay within the mounted preview; browser history routing is not implemented.

## Preserved design and behavior

- Reuses approved Rekenen 4.1, Taal 1, Spelling 1, Redactiesommen 2 and Begrijpend Lezen 3 via their existing definitions and `ExerciseScreen`. No copied exercise markup, new colors, typography, artwork, animation or message wording. The original subject workbenches retain their own scenario/reset controls.
- Original question sequence and content remain fixed. First misses queue the identical question after the originals, in miss order, without a retry interstitial. First miss and correct retry reveal no solution. A second miss shows the existing authored explanation and ends that question. Feedback/result submissions cannot add attempts.
- Child-facing results count solved original questions, including successful retries. Internal weighted points remain 1/0.5/0, separate from solved counts. No mastery, motivation or attention inference.
- Reading retains the whole passage, question/choice order and selected answer through navigation, retries and explanation. Its approved wide layout, mobile stacking, full-size Nexai and absence of jump links remain intact. Production reveal-dependency/assisted-evidence logic is still absent.
- Spelling preserves internal spaces, accents and punctuation as attempted spelling under its approved fixture policy. No normalization or validation-policy change.
- Task identity is explicit, never inferred from its display label. The second Rekenen task shows task 2 in the exercise and summary. Task statuses and the block completion count derive from that task's state. No task becomes done before the result transition.
- Task return focuses its **Ga verder** or **Bekijk resultaat** button; initial overview focuses its heading; block return focuses **Bekijk taken**. Exercise entry/resume focuses the answer or feedback/result region, with the existing Enter/Tab/radio-arrow behavior retained.
- The connected result omits the standalone **Voorbeeld opnieuw proberen** workbench control so it cannot erase completed task evidence. Reopening a completed task shows its result. Refresh deliberately resets the entire temporary preview.
- The reused block card omits its gamepas section and reward-entitlement sentence in this connected context. Completion does not issue, activate or qualify a pass. Historical card specimens retain their existing default presentation. The card accepts heading level 2 for the new page's heading hierarchy.

## Ownership and implementation

- `src/modules/practice/journey/practice-journey.tsx`: explicit synthetic assignments, page navigation and a task-ID-keyed snapshot map, owned by one mounted practice preview. `practice-journey-state.ts` contains the small status projection/type.
- `exercise/exercise-definition.ts`: optional controlled snapshot/navigation contract. Each snapshot includes lifecycle state, draft answer and validation error. `ExerciseScreen` uses it when connected, otherwise its existing local state.
- `exercise/exercise-preview.ts`: existing lifecycle plus append-only local submitted-attempt records (index, original/retry, submitted answer, correctness). Queue, cursor, outcomes and current submission remain in the same state object. Scenario shortcuts remain illustrative snapshots; no fabricated attempt history is inferred for them.
- Each subject exports its existing definition; content and answer policies stay in the subject folder. The reading initializer takes its count from the question bundle. Accessible progress and preview count text use the state length.
- `practice-block/practice-tasks-page.tsx`: overview presentation and callbacks replace the placeholder exercise branch. Shared styles/tokens, task-message selection and backdrop remain reused. `exercise-summary.tsx` accepts a return callback and optional standalone reset.
- `practice-journey.stories.tsx` and `tests/e2e/practice-journey.spec.ts`: connected review and regression evidence. Shared-lifecycle tests cover retained submissions and non-ten question counts.

This follows ADR-009's local exercise ownership. No new global store, service, dependency, production route or database model is needed. No architecture replacement or new product policy was required. The prior claims that exercises are unconnected and that leaving the task always resets progress are historical for this connected entry; standalone previews still reset on leaving. All subject design approvals remain in force. The user explicitly approved this navigation/temporary-state integration as revision 1 on 19 October 2026; its approval is separate from the earlier subject decisions.
